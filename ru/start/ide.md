# Проект в IDE

Писать скрипты можно и в блокноте, но с IDE получаешь автодополнение по всему API, проверку типов и переход к определению. Настраивается один раз.

## Что скачать

Папка для разработки скриптов лежит на сайте. В ней уже всё готово:

| Путь | Что это |
|---|---|
| `*.kts` | твои скрипты — `example.kts` лежит как отправная точка |
| `assets/` | шрифты, картинки и данные, которые читают скрипты — см. [папку assets](../extras/assets.md) |
| `.sdk/nursultan-script-api-vN.jar` | само API и шаблон скрипта, по которому IDE понимает, что такое `.kts` в этой папке |
| `.sdk/nursultan-script-packets-<версия>.jar` | классы пакетов Minecraft, нужны только если скрипт их читает или шлёт |
| `build.gradle.kts`, `settings.gradle.kts` | подключают эти джарки |
| `README.md` | те же шаги настройки, что и на этой странице, но офлайн |

`.sdk/` — сгенерированная папка, внутри ничего не правь. Обновляешь SDK — меняй её целиком.

## Открыть в IntelliJ IDEA

`File → Open`, выбери папку, «Open as Project», доверь проект. Gradle синкается один раз и качает только Kotlin-плагин.

## Обязательный шаг: определение скрипта

IntelliJ сам не находит кастомные определения скриптов, поэтому один раз на проект нужно ткнуть его носом:

> **Settings → Languages & Frameworks → Kotlin → Kotlin Scripting**
> → в разделе *Custom Definitions* нажать **Search Definitions**
> → в списке появится **Nursultan Script** (`.kts`)
> → оставить включённым и **выше** *Default Kotlin Script* → **Apply**

Без этого все `.kts` будут красными. Резолв считается по файлу, так что после настройки открой любой скрипт, чтобы IDE его пересчитала. Если ссылки всё ещё не резолвятся — `File → Invalidate Caches → Invalidate and Restart`.

## Перенос в игру

Готовый скрипт — это один `.kts`. Скопируй его в папку скриптов клиента (`%APPDATA%\Nursultan\scripts`) и включи во вкладке Scripts. Больше ничего копировать не надо: ни `.sdk`, ни сборочные файлы.

Если скрипт читает шрифты, картинки или данные, эти файлы едут вместе с ним — в `%APPDATA%\Nursultan\scripts\assets`, с теми же подпапками, что были при разработке.

Сохранение уже загруженного файла перезагружает скрипт на лету — перезапускать игру ради правки не нужно.

## Разработка прямо в игровой папке

Если не хочешь ничего копировать, можно писать сразу в папке скриптов клиента: положи туда `build.gradle.kts`, `settings.gradle.kts` и `.sdk/`. Клиент увидит, что это проект, и будет сам обновлять `.sdk` при каждом запуске. Если этих файлов там нет, клиент папку не трогает.
