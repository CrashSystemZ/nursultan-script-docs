# Папка assets

Шрифты, картинки и любые другие файлы, которые читает скрипт, лежат в одном месте: `%APPDATA%\Nursultan\scripts\assets`. Клиент создаёт эту папку сам рядом со скриптами, и любой путь, который принимает API, считается от неё.

```kotlin
font("myfont", "fonts/my-font.ttf")          // scripts/assets/fonts/my-font.ttf
val logo = image("images/logo.png")          // scripts/assets/images/logo.png

val greeting = assets.text("messages.txt")
val palette = assets.bytes("palette.bin")

if (assets.exists("images/logo.png")) {
    // ...
}

for (name in assets.list("images")) {
    // "logo.png", "mark.png", …
}
```

Подпапки придумываешь сам — клиент создаёт только саму `assets`.

## Чтение файла

| Вызов | Что вернёт |
|---|---|
| `assets.exists("data.json")` | `true`, если файл на месте |
| `assets.text("data.json")` | файл строкой (UTF-8) или `null` |
| `assets.bytes("logo.png")` | файл массивом байт или `null` |
| `assets.list()` | имена файлов в `assets` |
| `assets.list("images")` | имена файлов в `assets/images` |

Исключений тут нет. Файла нет, папки нет, путь клиенту не понравился — получишь `null` или пустой список и одну строчку в консоли скриптов с именем файла.

`list()` отдаёт имена, а не пути, и только файлы: подпапки не возвращаются, вглубь не заходит. Имя скармливай обратно вместе с папкой, которую спрашивал:

```kotlin
val icons = assets.list("images").filter { it.endsWith(".png") }
val first = image("images/" + icons.first())
```

Чтение не бесплатное — файл каждый раз идёт с диска. Прочитай его один раз наверху скрипта или на включении, положи в переменную и не читай ничего в обработчике тика или рендера.

## Чего клиент не прочитает

Путь считается от `assets` и за пределы `assets` не выходит:

* `..` в любом виде, абсолютный путь, буква диска, сетевой путь — отказ;
* ссылка, ведущая наружу из `assets`, — отказ, даже если сам путь выглядит безобидно;
* файл больше 8 МиБ — `text()` и `bytes()` его не отдадут;
* папка, в которой больше 1024 файлов, — `list()` вернёт первые 1024 имени и скажет об этом.

Остального диска для скрипта не существует: открыть файл по полному пути нельзя, и записывать файлы API не умеет вообще. Для своих данных есть [конфиги](../settings/storage.md).

## Ассеты внутри скрипта

Скрипт, который раздают одним `.kts`, может нести свои файлы прямо в себе — в base64, и пользователю не надо качать ничего лишнего:

```kotlin
val LOGO = base64(
    "0YXRg9C5INGF0YPQuSDRhdGD0Lkg0YXRg9C5INGF0YPQuSDRhdGD0Lk=",
    "0LbQvtC/0LAg0LbQvtC/0LAg0LbQvtC/0LAg0LbQvtC/0LA=",
)

val logo = image("logo", LOGO)               // декодируется один раз и кэшируется
font("myfont", base64(FONT_PART1, FONT_PART2))

on<Render2DEvent> { e ->
    e.render().texture(logo ?: return@on, 10f, 10f, 59f, 105f)
}
```

Текст берётся из любого энкодера — например [base64encode.org](https://www.base64encode.org/ru/): выбираешь файл, копируешь результат.

| Вызов | Что вернёт |
|---|---|
| `base64(vararg parts)` | `ByteArray`; если текст не base64, скрипт не загрузится и скажет файл и строку |
| `base64Encode(bytes)` | `String` — обратное преобразование, пригодится, чтобы положить свои данные в [конфиг](../settings/storage.md) |
| `image(name, png)` | `Texture?`, декодируется один раз и кэшируется под именем `name` |
| `font(name, ttf)` | семейство шрифта из байт, то же самое, что `font(name, файл)` |

**Длинный блоб режь на несколько строк.** Один строковый литерал в скомпилированном классе не может быть больше 64 КБ, а `"a" + "b"` Kotlin сворачивает обратно в один литерал — поэтому шрифт или крупный PNG приходится передавать отдельными аргументами, а `base64(part1, part2, part3)` склеивает их уже в рантайме. Внутри куска пробелы и переводы строк игнорируются, а префикс `data:image/png;base64,` отрезается, так что можно вставлять ровно то, что выдал энкодер.

`name` в `image(name, png)` — это ключ кэша, а не путь: по тому же имени вернётся та же текстура без повторного декода, имена не пересекаются между скриптами, а текстура освобождается, когда скрипт выгружают. Декодируй на верхнем уровне скрипта или в `onEnable` — но не в обработчике рендера или тика.

Лимит в 8 МиБ на ассет действует и здесь. И помни, что всё встроенное лежит в исходнике: шрифт на 200 КБ — это 270 КБ текста в `.kts`.

## Файлы старых скриптов

До появления `assets` шрифты и картинки лежали прямо в папке скриптов. Так тоже работает: если файла нет в `assets`, клиент посмотрит рядом со скриптом и один раз попросит в консоли перенести его. Новые скрипты должны класть файлы в `assets` — `exists()`, `text()`, `bytes()` и `list()` больше никуда не смотрят.

## Что учесть

* Клиент создаёт `assets` при запуске, пустой; подпапки внутри — на твоё усмотрение.
* Эти файлы придётся находить не только тебе: если скрипт тащит с собой больше пары файлов, положи их в подпапку с именем скрипта.
* `null` из `text()` или `bytes()` — это нормальный ответ: обработай его и скажи пользователю, чего не хватает.
