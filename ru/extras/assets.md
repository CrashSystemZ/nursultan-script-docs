# Папка assets

`assets` — это `client.assets()`, чтение файлов из `%APPDATA%\Nursultan\scripts\assets`. `base64(...)` — альтернатива: превращает строковые литералы прямо в `.kts` в байты, из которых собирается шрифт или картинка. Всё на этой странице — API 2.

```kotlin
val greeting = assets.text("messages/hello.txt") ?: "нет файла"

val FONT = base64(
    "AAEAAAAOAIAAAwBgT1MvMg…",
    "…AAAAAAAAAAAAAAAAAAAA=",
)
font("myfont", FONT)

on<Render2DEvent> { e ->
    e.render().text(greeting, 10f, 10f, 12f, Colors.WHITE, "myfont")
}
```

## Чтение файла

| Метод | Тип | Описание |
|---|---|---|
| `assets.exists(path)` | `boolean` | true, когда путь ведёт внутрь `scripts/assets` и это обычный файл (API 2) |
| `assets.bytes(path)` | `byte[]?` | файл целиком, null при отказе, отсутствии, размере больше 8 МиБ или ошибке чтения (API 2) |
| `assets.text(path)` | `String?` | те же байты, декодированные как UTF-8, null при тех же условиях (API 2) |
| `assets.list()` | `List<String>` | отсортированные имена файлов прямо в корне assets, максимум 1024 (API 2) |
| `assets.list(directory)` | `List<String>` | то же для одной подпапки, пустой список, если путь не разрешился или это не папка; null, пустая строка и `"."` означают корень (API 2) |

Пути считаются от `scripts/assets`, разделитель любой — прямой или обратный слэш. Исключений тут нет: отказ, отсутствующий или слишком большой файл дают `null` или пустой список плюс одно предупреждение в консоли скриптов.
`list` отдаёт только имена файлов — без путей, без папок, без обхода вглубь.

## Что отклоняется

| Отклоняется | Что вернёт |
|---|---|
| `..` в любом сегменте пути | `null` / пустой список |
| абсолютный путь, буква диска или сетевой путь | `null` / пустой список |
| пустой, состоящий из пробелов или некорректный путь | `null` / пустой список |
| путь, реальная цель которого уходит из `scripts/assets` | `null` / пустой список |
| файл больше 8 МиБ | `null` из `bytes` и `text` |
| больше 1024 файлов в одной папке | первые 1024 имени, остальные пропущены |

Каждый случай один раз пишет предупреждение в консоль скриптов по этому пути. Открыть файл по абсолютному пути нельзя, и записывать файлы API не умеет — для своих данных смотри [Сохранение данных](../settings/storage.md).

## Ассеты внутри скрипта

| Метод | Тип | Описание |
|---|---|---|
| `base64(vararg parts)` | `ByteArray` | склеивает части и декодирует MIME-base64, пустой вызов даёт пустой массив (API 2) (бросает `ScriptApiException`, если это не валидный base64) |
| `base64Encode(bytes)` | `String` | обычный base64 одной строкой, обратное преобразование (API 2) |
| `font(name, ttf)` | `void` | регистрирует семейство TTF из байт, игнорируется при занятом имени, пустом массиве и размере больше 8 МиБ (API 2) |
| `image(name, png)` | `Texture?` | PNG из байт, кэшируется под именем `name`, null при пустом имени, пустых байтах и размере больше 8 МиБ (API 2) |

Склеенный текст может быть `data:` URL: всё до `;base64,` включительно отбрасывается, а префикс `data:` без этой метки бросает `ScriptApiException`. Пробелы и переводы строк внутри части игнорируются.
Один строковый литерал в class-файле не может быть больше 64 КБ, а `"a" + "b"` Kotlin сворачивает обратно в один — поэтому `base64` принимает vararg. `name` в `image(name, png)` — это ключ кэша, приватный для скрипта, а не путь; обе байтовые перегрузки перечислены и в [Рендере 2D](../ui/render-2d.md).

## Файлы старых скриптов

`font(name, file)`, `image(file)`, `client.fonts().register(name, file)`, `client.textures().image(file)` и `Render.image(file, …)` откатываются на корень папки скриптов, если файла нет в `scripts/assets`, и один раз пишут об этом в консоль.
`exists`, `bytes`, `text` и `list` отката не имеют — они читают только `scripts/assets`. `texture(identifier)` принимает ресурс-id Minecraft, а не файл, и не трогает ни ту, ни другую папку.
