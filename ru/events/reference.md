# Список событий

Отменяемые события помечены в колонке «Отмена». Как подписываться и что значит приоритет — в [Подписке](basics.md).

## Тики

| Событие | Когда | Отмена |
|---|---|---|
| `ClientTickEvent` | каждый тик клиента, даже без мира | |
| `PrePlayerTickEvent` | перед тиком игрока | |
| `PlayerTickEvent` | внутри тика игрока, до расчёта движения | |
| `PostPlayerTickEvent` | тик игрока закончился — движение посчитано, пакеты уже ушли | |

`ClientTickEvent` идёт всегда, поэтому в нём почти всегда нужна проверка `if (!inGame) return@on`. `PrePlayerTickEvent` удобен, когда надо успеть что-то сделать до того, как игрок посчитает своё движение за этот тик. `PostPlayerTickEvent` — другой край: в нём видно, куда тик тебя в итоге привёл.

## Движение

| Событие | Когда | Отмена |
|---|---|---|
| `MovePacketEvent` | прямо перед отправкой пакетов позиции и поворота за тик | да |
| `MoveEvent` | перед применением перемещения игрока, `movement()` можно переписать | да |
| `TravelEvent` | перед ванильной физикой движения за тик | да |
| `MoveRelativeEvent` | после того как ввод движения превратился в скорость, только чтение | |
| `EntityPushEvent` | сущность толкает тебя или ты её | да |
| `BlockPushEvent` | игра выталкивает тебя из блока, в котором ты застрял | да |
| `WebCollisionEvent` | ты коснулся паутины, `x()`/`y()`/`z()` паутины | да |
| `TimerEvent` | каждый кадр, когда игра решает, сколько тиков прокрутить | |

`MovePacketEvent` — последняя точка, где позиция, которую увидит сервер, ещё твоя. Каждое поле и читается, и пишется: `x()`, `y()`, `z()`, `yaw()`, `pitch()`, `onGround()`, `sprinting()`. Отмена — за этот тик не уйдёт вообще ничего, сервер останется с прошлой известной позицией.

```kotlin
on<MovePacketEvent> {
    it.y(it.y() - 0.05)
    it.onGround(true)
}
```

`MoveEvent` — уровнем ниже: `movement()` это дельта, на которую игрок сейчас сдвинется, уже после ввода и физики, но до коллизий. Перепиши её, чтобы поменять, куда ты реально поедешь.

```kotlin
on<MoveEvent> {
    it.set(it.x() * 1.4, it.y(), it.z() * 1.4)
}
```

`TravelEvent` ещё ниже — отмени, и ванильная физика за этот тик не отработает совсем: ни гравитации, ни трения, ни ввода. Пока не подвинешь себя сам, ничего не сдвинется.

`MoveRelativeEvent` только сообщает: `speed()` — ускорение, которое применила игра, `input()` — сырой ввод движения. Записывать в него нечего, значение уже применено.

`TimerEvent` несёт `timer()` — множитель скорости игры на кадр, `1f` это норма. Каждый кадр он сбрасывается в `1f`, так что ставь его заново каждый раз.

```kotlin
on<TimerEvent> { it.timer(1.6f) }
```

Число ничем не ограничено: `0f` останавливает время и дальше делится в бесконечность, отрицательное крутит его назад. Держи в разумных пределах. Модуль Timer самого клиента пишет то же значение, так что победит тот, кто отработает последним — нужен ты, ставь `Priority.LAST`.

## Бой

| Событие | Когда | Отмена |
|---|---|---|
| `AttackEvent` | ты бьёшь сущность, `target()` | да |
| `AttackedEvent` | удар прошёл, `target()` | |
| `UseItemEvent` | начинается использование предмета, `hand()` | да |
| `StopUsingItemEvent` | клиент собирается отпустить ПКМ — отмени, чтобы доесть/допить/дозарядить | да |
| `FinishUsingItemEvent` | предмет доиспользовался — еда съедена, зелье выпито, `item()` | |
| `RightClickEvent` | клиент собирается обработать правый клик, `hand()` | да |
| `JumpEvent` | игрок прыгнул | |
| `SlowdownEvent` | игра замедляет движение (еда, щит, лук); `multiplier()` можно переписать | |
| `TargetUpdateEvent` | у клиента сменилась боевая цель | |

`TargetUpdateEvent` несёт `previous()` и `target()` — оба могут быть null, а `lost()` это короткий способ спросить, пропала ли цель. Это цель *клиента*, её публикует тот боевой модуль, который сейчас работает (AttackAura, TriggerBot, AimAssist) — если ни один не включён, событие не придёт вообще.

## Блоки

| Событие | Когда | Отмена |
|---|---|---|
| `BlockHitEvent` | клиент начинает или продолжает ломать блок, `x()`/`y()`/`z()`, `side()` | да |
| `BlockBreakingEvent` | раз в тик, до того как клиент продвинет копание | да |
| `BlockPlacedEvent` | ты поставил блок, `block()` | |

`BlockBreakingEvent` приходит каждый тик, пока ты в мире, а не только пока копаешь — что именно происходит, говорит `breaking()`. Отмена выкидывает шаг копания за этот тик целиком, вместе с той частью, которая останавливает копание, если ты уже отошёл, так что отменяй на тех тиках, где это осмысленно, а не подряд.

`BlockPlacedEvent` — только твои постановки: событие идёт из предсказанной клиентом установки, поэтому блоки, которые ставят другие игроки, в него не попадают — они приезжают обычным обновлением блока. Отдаёт полноценный [`Block`](../game/world.md), так что `id()`, `position()` и всё остальное лежит прямо на нём.

## Инвентарь

| Событие | Когда | Отмена |
|---|---|---|
| `SlotClickEvent` | кликнули по слоту в открытом контейнере | да |
| `EffectEvent` | эффект на твоём игроке добавился, обновился или спал | |

`SlotClickEvent` несёт `syncId()`, `slotId()`, `button()`, `action()` и `item()` — стак, который сейчас лежит в слоте. Отмени, и клик не дойдёт до сервера.

```kotlin
on<SlotClickEvent> {
    if (it.action() == SlotAction.THROW) it.cancel()
}
```

`EffectEvent` несёт `effect()` и `action()`. `action()` это `ADD`, `UPDATE`, `REMOVE` или `PLAYER_INIT`; на `PLAYER_INIT` игрок только создаётся и `effect()` равен `null`.

## Ввод

| Событие | Когда | Отмена |
|---|---|---|
| `KeyEvent` | нажата или отпущена клавиша или кнопка мыши | да |
| `CharEvent` | введён символ | да |
| `MouseScrollEvent` | колесо мыши | да |
| `MoveInputEvent` | собран ввод движения за тик, поля можно переписать | да |
| `LookInputEvent` | движение мыши, `deltaX`/`deltaY` можно переписать | да |

`KeyEvent` несёт `key()`, `mods()`, `action()`, плюс короткие `pressed()`, `released()`, `mouse()` и `matches(Key.G)`.

`MoveInputEvent` — это то, что игра собирается сделать: `forward()`, `backward()`, `left()`, `right()`, `jump()`, `sneak()`, `sprint()`. Каждое поле можно и прочитать, и записать:

```kotlin
on<MoveInputEvent>(priority = Priority.LAST) {
    it.sprint(true)
    it.jump(true)
}
```

## Мир и сущности

| Событие | Когда | Отмена |
|---|---|---|
| `EntitySpawnEvent` | сущность появилась, `entity()` | |
| `EntityRemoveEvent` | сущность пропала, `entity()` | |
| `WorldLoadEvent` | загрузился мир — заходишь на сервер, меняешь измерение | |
| `ScreenCloseEvent` | закрылся экран (инвентарь, сундук, меню) | |
| `PlaySoundEvent` | мир собирается проиграть звук | да |
| `PotionImpactEvent` | брошенное зелье во что-то попало | |
| `ServerConnectEvent` | ты начал подключаться к серверу | |

`WorldLoadEvent` — хорошее место, чтобы сбросить всё, что привязано к конкретному миру.

`PlaySoundEvent` даёт на чтение `id()` и `category()`, а на чтение и запись — `volume()`, `pitch()`, `x()`, `y()`, `z()`. Отмена — тишина.

```kotlin
on<PlaySoundEvent> {
    if (it.id() == "minecraft:entity.player.levelup") it.cancel()
}
```

`PotionImpactEvent` срабатывает один раз на зелье и несёт `potion()`, `position()` и `hitEntity()` — последнее равно `null`, если зелье попало в блок, а не в сущность.

`ServerConnectEvent` несёт `host()`, `port()` и `address()` и приходит до загрузки мира — раньше, чем `WorldLoadEvent`.

## Пакеты

| Событие | Когда | Отмена |
|---|---|---|
| `PacketReceiveEvent` | пришёл пакет от сервера, `packet()` | да |
| `PacketSendEvent` | клиент собирается отправить пакет, `packet()` | да |

Вызываются **на сетевом потоке**. Подробности и список пакетов — [Пакеты](../actions/packets.md).

## Отрисовка

| Событие | Когда | Отмена |
|---|---|---|
| `Render2DEvent` | каждый кадр, слой оверлея клиента | |
| `Render3DEvent` | каждый кадр, в мире | |
| `BlockOutlineEvent` | игра собирается нарисовать обводку блока, на который ты смотришь | да |
| `CameraEvent` | позиция и поворот камеры на кадр, всё пишется | да |
| `SwingSpeedEvent` | игра спрашивает, сколько длится взмах рукой | |
| `RenderItemEvent` | перед применением трансформации взмаха предмета от первого лица | да |
| `FramebufferResizeEvent` | окно поменяло размер | |

`Render2DEvent` несёт `render()`, размер экрана `width()` × `height()` и `tickDelta()`. `Render3DEvent` несёт `render()`, `tickDelta()` и позицию камеры `camera()`. Смотри [Рендер 2D](../ui/render-2d.md) и [Рендер 3D](../ui/render-3d.md).

`BlockOutlineEvent` несёт координаты блока `x()`, `y()`, `z()` и `box()` — форму обводки в мировых координатах, так что у полублока коробка будет в половину высоты. Отмени его — ванильной обводки не станет, а свою нарисуй в `Render3DEvent`:

```kotlin
var target: Box? = null

on<BlockOutlineEvent> { e ->
    e.cancel()
    target = e.box()
}

on<Render3DEvent> { e ->
    e.render().box(target ?: return@on, Colors.CYAN, false)
}
```

Вызывается во время отрисовки мира, раньше обоих событий отрисовки того же кадра, так что сохранённое значение всегда свежее. Как только отвёл прицел — событие перестаёт приходить, поэтому чисти свою копию в `ClientTickEvent`, если за тик ничего не пришло.

`CameraEvent` даёт `yaw()`, `pitch()`, `x()`, `y()`, `z()` — всё и читается, и пишется. Отмена пропускает остаток обновления камеры — дистанцию в третьем лице и наклон во сне, — но оставляет значения, которые ты выставил.

`SwingSpeedEvent` несёт `durationTicks()`: сколько тиков длится один взмах, по умолчанию `6`. Уменьши — анимация станет быстрее, но не до `0`: на это число прогресс взмаха делится.

`RenderItemEvent` несёт `arm()` и `swingProgress()`. Отмени — трансформация взмаха не применится, предмет останется неподвижным в руке.

`FramebufferResizeEvent` несёт `width()` и `height()` в настоящих пикселях — в том же пространстве, где рисует `Render2DEvent`. Пригодится, чтобы выкинуть всё, что ты посчитал под старый размер окна.

## Модули

| Событие | Когда | Отмена |
|---|---|---|
| `ModuleToggleEvent` | включили или выключили модуль клиента либо скрипт | |

Несёт `name()`, `enabled()` и `fromScript()` — последнее показывает, это был скрипт или встроенный модуль.

## Что такое tickDelta

Игра думает 20 раз в секунду, а рисует гораздо чаще. `tickDelta` — это доля от 0 до 1, показывающая, насколько далеко кадр ушёл от последнего тика. Нужна, чтобы движение на экране было плавным, а не дёргалось 20 раз в секунду.
